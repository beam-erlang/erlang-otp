# SNMP assembly

SNMP 5.20.3 owns its Erlang agent, manager, MIB compiler and protocol codecs.
CMake builds 88 retained modules and two generated modules, with application
and upgrade resources under `lib/snmp-5.20.3`. It uses the installed BEAM
compiler host and the explicitly source-built ASN.1 and parser tools. No
additional VM service, private header or native artifact is needed.

The retained experimental `snmpa_general_db` is excluded, matching the upstream
product inventory and application resource.

The build first generates the Yecc MIB parser and the BER codec from
`snmp_pdus_basic.set.asn`. A source-built MIB compiler seed, with `snmp_misc`,
then generates 18 standard compiled MIBs and their public headers in dependency
order. Its application directory is explicit on the compiler host's code path;
ordinary `code:priv_dir(snmp)` lookup resolves this build tree. Only after these
headers exist does the full application compile. Behavior modules precede their
implementations. The build preserves the version and `app_vsn` attributes,
default verbosity `silence` and default empty-PDU size 21.

The installation includes compiled MIBs, generated and retained public headers,
SMI schemas and instrumentation mappings, configuration templates, module sources,
generated parser/codec sources, and the retained `snmpc` escript with its version
substituted. The SNMPv1 example MIB is generated by the retained Perl/sed
converter. Perl no longer permits nonzero `$[`: the converter explicitly pads
its field array to preserve its one-based indexing. Comments are handled before string tracking so quoted
license text cannot leave the converter in string state and retain invalid
SNMPv2 declarations in its SNMPv1 output. This is a product build-tool
adaptation; upstream test sources and fixtures remain untouched.

## Acceptance boundary

The product checks compile an installed MIB through `snmpc`, generate its public
header through `erlc`, and compile the installed converted SNMPv1 MIB. The Erlang
probe configures an agent and manager on loopback UDP, registers an agent, and
reads its system name over both `inet` and `socket` backends. Application shutdown
is checked before repeating on each of three boots. Relocated and isolated
checks exclude the original SDK and source/build trees.

The unchanged upstream harness selects these complete suites:

| Suite | Cases |
| --- | ---: |
| `snmp_app_SUITE` | 2 |
| `snmp_compiler_SUITE` | 16 |
| `snmp_pdus_SUITE` | 4 |
| `snmp_conf_SUITE` | 17 |

The harness copies and hashes suite sources, support modules and data, compiles
them with the installed candidate, and executes from a relocated installation
in filesystem isolation. Private cookies and EPMD support candidate peer nodes. The original
`snmp_test_data` define and copied shared data directory are supplied explicitly;
the retained `Test2.mib` is compiled before the augmentation case imports it.
Zero failures and zero skips are required for each selected suite to pass.

Final evidence on each flavor is **35 passed, zero failed and four skipped
cases**. The application and PDU suites pass completely. The compiler suite
reports 14 passes and two explicit `not_yet_implemented` skips (`imports` and
`module_identity`); the configuration suite reports 15 passes and two explicit
`not_implemented_yet` skips (`read` and `read_files`). Their strict gates remain
nonpassing. Skips are not compatibility evidence and are not suppressed.

Both relocated and isolated product checks pass on both flavors. The initial
JIT checks exposed missing test-build defines and the converter problems above.
The subsequent application-suite failure identified `snmpa_general_db` as an
extra compiled module. After correcting the build inventory, the complete
application suite and both product checks pass again. Final results combine
these focused rechecks with the unchanged compiler/PDU/configuration suite runs;
they do not claim the initial matrix passed.

Broader agent/manager, authentication, notification, storage, OS Monitor and
external interoperability coverage remains required. This selection does not
establish full SNMP or OTP compatibility.

## Source and artifact checkpoint

Sources are OTP `72a1beb074a9fb8481d652418db80255c2962008` and BEAM
`795e3ac7fa39433cce26bc979bd8889da324d52a`, with the recorded uncommitted work.
SDK identities and hashes remain those in [Diameter evidence](diameter.md).
This increment changes no VM/SDK code, retained Erlang application sources,
upstream test assertions/fixtures or bootstrap seeds. Its sole retained-source
adaptation is the Perl converter described above.

Both installations contain 28 application entries and 929 BEAM files. All 839
preceding files remain byte-identical; all execution-chunk sets match across
flavors. The 18 compiled MIBs and converted SNMPv1 schema also match. SNMP installs
21 public headers: three retained and 18 generated. Shared-runtime, playground
and matching GLM acceptance is carried forward from the unchanged SDK checkpoint,
not represented as newly executed validation. At this checkpoint, seven
application entries and broader compatibility remained pending; stage 4 and
[compatibility gates 2–5](../../dev-documents/otp-compatibility.md#completion-gates)
remained open.

## Reproduction

Build against the explicitly selected installed SDK, then run for both flavors:

```sh
ctest --test-dir build/linux-emu -R '^(initial-product|isolated-product|upstream-snmp_(app|compiler|pdus|conf)_SUITE)$' --output-on-failure
ctest --test-dir build/linux-jit -R '^(initial-product|isolated-product|upstream-snmp_(app|compiler|pdus|conf)_SUITE)$' --output-on-failure
```

Per-run `checks/upstream/<suite>-*/result.json` records source hashes, SDK
identity, selected cases and any skips. Workspace scratch logs use
`tmp/otp-snmp-{build,check}-{emu,jit}.log`.

Focused final inventory/product rechecks use `tmp/otp-snmp-inventory-check-*.log`.
The aggregate artifact and selected-suite record is `tmp/otp-snmp-artifacts.json`.
